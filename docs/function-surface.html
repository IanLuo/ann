The rhythm

idea → validate (idea confirmed) → envision → spec (the beginning steps) → then the loop:
run next (Ann proposes) or specify task (you steer) → the step runs → gate① card → gate② confirm (grill, confirm, or reject with feedback) → repeat.
status / history / artifact anytime · change = just specify an amendment task · check / resume / prune on maintenance.
Settled decisions (locked in functional-spec §2):
  • Default chain: idea → validate → envision → spec → continue — configurable per project (F3)
  • validate = the idea's exit gate — nothing proceeds from an unconfirmed idea
  • run next = pull (Ann proposes) · specify task = push (you propose) — both converge on the gate card
  • card = gate presentation — every task's first step; no standalone card function
  • change has no dedicated function — a change IS specifying an amendment task (F6); AC-7 served by F6
  • Deep per-function detail → slice task contracts during the build; this spec fixes surface + interaction shape
