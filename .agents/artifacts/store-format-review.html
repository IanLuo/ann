Tree-Format Spec v3 — Store Review

Audit of the locked data contract vs. the tree that uses it · every element below is clickable to annotate

Findings — drift between spec and practice

real Task placement inconsistent

R2/R3 tasks sit flat under the round (02-grilling/01-spec-rework, 03-tree-format/01-depth-policy); R4/R5 use the spec's 00/ task group (05-engine/00/01-…). The spec §1 mandates 00/ = the task group — two shapes exist in one tree.

Position: keep historical, no hot migration (spec §10 forbids restructuring existing trees). Document the two shapes as legacy + standard; the validator tolerates both; new tasks always use 00/.

real spawned event is vestigial

Spec §3 lists spawned (with parent+order) as an event type — zero events use it. Children are structural (directories) now; it's leftover from the old flat model.

Position: remove spawned from the spec — the child's created event IS the spawn record.

real requiredInputs use paths + shas, not logical names

Spec §1/§2 say previous artifacts are named by logical name; practice writes "R1 output: design §21 (locked @ eb07146)" — a historical snapshot, not a durable reference. Predates the resolution convention.

Position: new nodes use logical names; existing are historical (node.json is immutable). State this explicitly.

real at is date-only — ordering ambiguity

Events carry "at":"2026-08-16". Two events for the same name on the same day can't be ordered by timestamp. The resolver's "latest" currently uses a sha tiebreak — a hack.

Position: ordering = append order within a file (already the design); at is informational. Resolution correctness comes from the one-current-per-name validator + superseded events, not timestamp sorting. Fix the resolver tiebreak; state this in the spec.

minor Name discipline violated

Three task names exceed the ≤24-char rule (§8): 08-system-design-validation (27), 05-requirements-amendment (25), 03-change-protocol-amendment (29).

Position: keep (no hot migration); enforce for new nodes.

minor Card lines + schema enumeration

17 cards exist; 11 carry the required round goal met? / group position: lines. §2 says "schema unchanged from v2" without enumerating node.json fields — S1 needs the exact schema.

Position: enumerate the node.json schema inline; cards converge on the required lines as derived views.

What passed — no action

  • Immutability + append-only enforced in practice; status derivation correct (superseded-annotates works on the live tree)
  • Resolution works end-to-end (v1→v2→v3 chains; 8 current artifacts verified)
  • Depth budget · prefix ordering · one-store-per-project · multi-user-ready note all hold
  • --check (files exist, one current per name) passes

The decision

Six findings → one format v4 amendment (per the change protocol: amendment node → complete superseding doc → supersede v3 → lock). The positions above are recommendations — confirm or override, especially task placement (keep legacy) and drop spawned.
