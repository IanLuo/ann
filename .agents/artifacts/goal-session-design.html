2 · The goal leg (legacy shape — reviewer C1/C2)

Goal = the designated SEEDED CHILDLESS leg, not “frontmost leg”: a 01-goal-named leg that carries tasks is an ordinary work leg, not the goal. Its seed marks it.
Status must derive done: seed writes created + completed on the goal leg root (legacy 01-goal shape) so legStatus reads done and the first work leg's gate (legGateMet) opens. Status-inert alone would hard-block all work.
Root-event exception, id-scoped: the designated childless goal leg may hold seed (created/completed), artifact-locked (goal.md), and goal-met. Nothing else on leg roots. goal-met is status-inert.

3 · The stability ladder

  GOAL     goal.md (locked) + generated node  — IMMUTABLE per session (changed goal ⇒ NEW SESSION)
    │
  SPECS    docs-in-force — revisable INSIDE the goal; the reject rule ships WITH the specs tier
    │
  TASKS    adjust code / small functions; MAY revise a spec; never the goal
    │
  RUN      the realized journey
Reject rule is DEFERRED, not advertised: supersede! is content-blind today, so “specs cannot override the goal” is only enforceable once the specs tier lands (a scripted gate naming the goal ACs a spec touches; contradiction judged at the human gate). Until then the MVP must not claim it as enforced.
All-done ⇒ a CHOICE: (1) new goal (criteria met) · (2) add a task under the same goal (spec refinement = an ordinary superseding task) · (3) subtle task (e.g. quality gate). Session ends only when the human says met.
Discriminator: success criteria, not size. Same criteria → task; criteria change → new goal/session.

4 · goal! met (guarded)

Human-initiator only (refuse an automated RECORDED_BY) · refuse double-met · refuse while any undecided submission exists (a done task can still hide one) · refuse post-met spawns (a stale verdict is never silently carried). No reopen yet — a wrong met is recoverable only via the specced archive override path.

5 · next = four-state consult

no goal (empty) → grill + seed · seeded, no work → open (first task) · exhausted, unconfirmed → offer the choice menu · met → session complete → archive/new goal. Never the blind “journey goal complete”.

6 · goal! archive (significant, guarded, dogfoodable)

Guard is scoped: requires goal-met (or an explicit override) and refuses only new check/verify problems + uncommitted tracked changes — never this repo's known 15/4 baseline or untracked scratch. A specced override path exists so the feature can archive its own journey.
Destination round-trips Store(): .ann/archive/sessions/<ts>-<slug>/journey/{legs, .ledger.json} so an archived session loads read-only; the live ledger entry is removed (else verify reports node-deleted). Id reuse across sessions is then safe.

7 · Docs-in-use = DERIVED index (reviewer M8)

No on-disk .ann/docs layer (leg 07 deleted it; e2e asserts it's gone; a store-unwalked folder silently goes stale). The index of in-force docs IS the derived ann specs table (current()-based) — always current, never duplicated.
Optional browseable folder (your “factory docs”): generate it at project root docs/ — scripted + committed like README regen, never read by the store. Decide here whether to ship it in the specs tier.

8 · The specs tier = one deferred whole

Seed does NOT run the specs routine in the MVP: goal.md only; specs appear when a task's shaping flow produces them (today's model). The specs tier (spec docs + reject rule + docs folder) lands together as one scripted slice — never piecemeal. Re-grill is allowed BEFORE goal.md + node are sealed (grilling can surface criteria that belong in the goal).
