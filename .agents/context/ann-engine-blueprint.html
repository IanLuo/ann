The layer stack

Five layers, one rule: only L1 writes. The engine's invariants live in the six mutators; the store is never hand-edited and never written around. Reads are derived views — recomputed, never stored twice.

Figure 2 · the command surface

Where every command lands

The CLI is a binding, not an initiator: each of the 32 commands dispatches to exactly one destination. The six mutators are the only journey-event writers; the reads are derived views; run! hands off to the frame; the config trio never writes the journey at all.

Figure 3 · the mechanism

The frame — one pass, resumable

run! drives a task through a fixed frame: materialize → grill → validate → activate → execute → verify → confirm → commit. The two gates are where a human decides; everything else is deterministic work over derived state.

TAIL STATE 1

confirmed at a gate — skip the gate write; the step still re-runs from the transcript.

TAIL STATE 2

submitted, undecided — block and wait for the human; an interrupted gate stays blocked.

TAIL STATE 3

last decision rejected — the rework rung runs; the gate is re-obtained.

TAIL STATE 4

waiting, no commit evidence — the empty-chain verify-wait; block until the commit lands.
